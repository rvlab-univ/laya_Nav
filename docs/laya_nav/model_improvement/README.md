# LayaNav 모델 개선 기록

개선 버전마다 문서 하나를 둔다.

| 버전 | 내용 | 상태 | 체크포인트 (서버 `checkpoints/`) | 문서 |
|---|---|---|---|---|
| v1 | LayaNav 최초: Laya-S2 판단 + 경로 헤드로 DualVLN System 1 대체 | 학습 완료, 경로 예측 나쁨 | `laya_nav_c1` | [구현 보고서](../IMPLEMENTATION_REPORT.md) |
| v2 | System 1: 경로 헤드 보강(프레임 융합, 목표 표시, 출발 지점 4개) + 큰 데이터셋 | 학습 완료. 정답 목표 경로 오차 0.09 m. 병목은 System 2 목표 선택(정확도 0.45), 판단 과적합 | `laya_nav_mix_c1`, `laya_nav_mix_c2` | [v2_path_head.md](v2_path_head.md) |
| v3 | System 2: 지시문–화면 연결(SigLIP2 근거 지도, 지시문 짝 맞추기) | 학습 완료. 물체 이름에 반응하기 시작(KIMM TVD 0.017 → 0.041, 근거 지도 효과). 목표 정확도는 그대로(0.45) | `laya_nav_v3_c2` | [v3_grounding.md](v3_grounding.md) |

## 이름 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 문서 | `vN_<주제>.md` (영문 소문자, 밑줄) | `v3_grounding.md` |
| 그림 | `figures/vN_<주제>.<png·svg·jpg>`. 그 그림을 쓰는 버전 문서의 번호 | `figures/v3_siglip_grounding.jpg` |
| 체크포인트 | `laya_nav_vN_<단계>` (단계: `c1`, `c2`) | `laya_nav_v3_c2` |
| 결과 노트 | `../results/<체크포인트 이름>.md`. 학습 한 번의 수치 기록이고, 버전 문서의 결과 절에서 링크한다 | `../results/laya_nav_mix_c2.md` |

v1과 v2 체크포인트는 이 규칙 이전에 만들어져서, 서버의 이름을 그대로 쓴다.

## 문서 구성

모든 버전 문서는 같은 순서로 쓴다.

1. **진단**: 무엇이 문제였고, 무엇으로 확인했나
2. **변경**: 무엇을 바꿨나 (구조도, 레이어 표)
3. **비용**: 파라미터, 시간, 메모리
4. **학습**: 서버 명령
5. **확인**: 무엇으로 효과를 확인하나, 기대 결과
6. **결과**: 학습 후 실제 결과 (학습 전에는 "학습 전"으로 둔다)
